# Единый персональный помощник: переход к PWA

Дата: 17 октября 2026. Статус: спецификация для проверки пользователем.

## Зачем

Пользователю нужен один привычный способ записать дело, увидеть встречи и
продолжить работу с другого устройства. Сейчас отдельные интерфейсы ощущаются
как разные инструменты. Успех: запись из Telegram видна в PWA, выбранное «Сейчас»
видно в виджете, завершение в любом интерфейсе меняет одну и ту же задачу.
Запись не требует заранее выбирать объект, дату или тип.

Принятые решения: основной интерфейс — PWA для компьютера и iPhone; сервер
хранит данные и правила; Telegram дополняет быстрым вводом; iOS обеспечивает
виджет, голос и системные действия. Согласованный образец —
`personal_assistant_workbench_v2.html`. Пользователь отверг мотивирующие
названия «В фокусе» и «Дальше по плану». Сохраняем обычные «Сегодня», «Задачи»,
«Расписание», «Входящие», «Идеи» и действие «Сейчас».

## Проверенная исходная точка

Репозиторий: Aev199/personal-assistant-2. Основа —
`feat/ios-primary-client`, коммит `bcc60dbb375fdda58538020c2c624bf9aa44efa2`.
`main` на `27e6e8159d06864547bf7a4e0542c793d79dd97d` старее и не подходит
как исходная точка перехода. Фактическая версия на VPS не проверялась.

- В свежей ветке Postgres уже хранит рабочие/личные задачи и идеи.
- `bot/http/companion.py` уже предоставляет today, tasks, projects, ideas,
  capture, intake, редактирование, завершение и выбор «Сейчас».
- `bot/services/native_intake.py` использует общие правила разбора ввода.
- `bot/services/calendar_today.py` получает календарь iCloud с ограничением
  времени ожидания. Ошибка календаря не должна блокировать задачи.
- Веб-приложения, manifest и service worker в проверенной ветке нет.
- Browser-входа нет: API принимает Bearer-токены приложения и виджета.
- Текущий список tasks сначала читает не более 500 записей, затем выдаёт не
  более 200. Это нельзя использовать как полноценный список всех задач.
- `/capture` сохраняет текст прямо в INBOX без обращения к LLM, но пока не
  обеспечивает повторяемость сетевого запроса без создания дубля.
- Доставка напоминаний через Telegram существует; действия iOS согласуют
  состояние на сервере. Отдельного планировщика локальных iOS-уведомлений
  в просмотренных исходниках не найдено. Единую доставку предстоит довести.

Это проверка исходников, а не подтверждение работоспособности сервера или iPhone.

## Выбранный подход

Развиваем существующий aiohttp-сервер. Он раздаёт PWA с того же адреса, что и
`/api/v1`; PWA и нативные клиенты вызывают существующие действия над одной БД.
Отдельный сервер, вторая база и синхронизация копий задач не нужны.

Рассмотрены альтернативы: отдельный frontend-сервис добавляет второй процесс
и настройку доступа между доменами; расширение только Swift не решает работу
на корпоративном компьютере. Для одного пользователя достаточно небольшого
веб-интерфейса на HTML/CSS/JavaScript без обязательного Node-процесса на VPS.

Общие операции над данными остаются на сервере. Нужные для PWA операции,
которых нет в API, добавляются совместимо; старые маршруты iOS сохраняются.
Локальные состояния интерфейса — открытый раздел, фильтр, черновик — могут
различаться на устройствах. Задачи, идеи, даты и «Сейчас» — общие.

## Первый рабочий этап

Цель этапа — подключённый к настоящим данным адаптивный веб-интерфейс.

1. На компьютере: боковая навигация; «Сегодня» с задачами и расписанием;
   «Задачи» с переключением работа/личное; «Входящие»; «Идеи».
2. На iPhone: нижние вкладки Главная / Задачи / Идеи; входящие доступны
   с главного экрана, работа/личное переключаются внутри задач.
3. Верхняя строка сохраняет запись во Входящие по Enter. Это поле ввода,
   а не имитация поиска. Черновик очищается только после подтверждения сервера.
4. Задачу можно открыть, изменить название/объект/дату, завершить и назначить
   «Сейчас». Выбор «Сейчас» один на пользователя, как в существующем сервере.
5. «Входящие» — представление существующих задач INBOX, без второй коллекции
   копий. Разбор записи в идею выполняется серверной транзакцией: исходная
   задача убирается из активного списка лишь после успешного создания идеи.
6. Идеи остаются отдельными от обязательств. Доступны перевод в задачу и архив.
7. Расписание показывает сегодняшние встречи iCloud. Отдельный многодневный
   редактор календаря в первый этап не входит. Интерфейс сообщает о недоступности
   календаря и времени последнего успешного обновления.
8. Раздел задач получает серверную пагинацию и фильтры до применения LIMIT.
   «Загрузить ещё» позволяет увидеть весь список; ограниченная подборка «Сегодня»
   никогда не называется списком всех задач. Просроченные даты видны явно.

Демонстрационные объекты, встречи и Windows-пути из макета не попадают в БД.
На первом этапе поля и ссылки на рабочие папки не добавляются: в текущем API
для них нет подтверждённой модели. Obsidian и файловый менеджер не объединяются
с помощником в этом изменении.

## Вход и сохранение

PWA работает с сервером на одном HTTPS-адресе. Пользователь один раз вводит
существующий токен приложения в форму подключения. Сервер проверяет его и
выдаёт ограниченную по сроку серверную сессию через HttpOnly/Secure/SameSite
cookie. Токен не сохраняется в localStorage, HTML, URL или service worker.
Есть выход и отзыв сессии; изменение исходного токена аннулирует старые сессии.
Создание сессии ограничено по частоте попыток. Секреты не попадают в журнал.
Запросы изменения защищены проверкой Origin и CSRF-токеном, связанным с сессией.
Bearer-доступ приложения и ограниченный токен виджета сохраняют прежние права.

Каждая новая запись из PWA получает уникальный client_request_id. Сервер
сохраняет его вместе с результатом в одной транзакции и при повторе возвращает
тот же результат. Тот же ключ с другим текстом отклоняется как конфликт.
Пользователь видит «Сохранено» только после ответа сервера. При сетевой ошибке
введённый текст остаётся, доступно повторение с тем же ключом. Редактирование
не должно без предупреждения перезаписывать более новую версию задачи;
обновления проверяют ожидаемый updated_at и предлагают перечитать конфликт.

При возврате к PWA она обновляет данные. Пока открыта — выполняет ограниченный
опрос сервера; скрытая вкладка прекращает опрос. Изменение из другого клиента
появляется при ближайшем обновлении. Реальный push между экранами не обещается.

## PWA и переход с iOS

Следующий отдельный этап: manifest, иконки, установка на главный экран и
service worker с версионированием только статической оболочки. Защищённые
API-ответы и токены не кэшируются. При отсутствии сети оболочка показывает
понятное состояние; полноценное автономное редактирование не входит в эту работу.
Установка и поведение на iPhone требуют проверки на устройстве пользователя.

Swift-приложение сокращается после проверки основных сценариев в PWA.
До этого существующие экраны и голос остаются доступны. Голос iOS продолжает
использовать распознавание устройства и серверный разбор. Запись звука из
браузера — отдельная задача, не условие первого рабочего этапа.

Виджет показывает серверные задачи и выполняет серверные действия; сам по себе
виджет не является каналом гарантированной доставки уведомлений. Целевой основной
канал — iOS. До отдельной реализации и проверки доставки сохраняется текущий
Telegram-канал. Переход должен выбирать один канал для каждого напоминания,
без одновременной отправки обоими; тихое отключение единственного рабочего
канала недопустимо. Новые уведомления PWA на первом этапе не добавляются.

## Границы реализации

Ожидаемые области изменений: `bot/http` для браузерной сессии и раздачи статики;
новая папка веб-ресурсов; небольшие расширения task/inbox API; DB-хранилище
сессий и ключей повторных запросов. Выделять общие операции в services следует
только там, где это нужно для повторного использования, без переписывания
всего `companion.py`. Регистрация маршрутов учитывает оба режима запуска
в `bot/runtime.py`. Изменения схемы добавочные и сохраняют прежние данные.

## Как принимаем результат

- Создать запись в Telegram → открыть PWA → увидеть ту же запись.
- Создать запись в PWA при недоступном Gemini → увидеть её во Входящих.
- Повторить запрос после потери ответа → получить одну запись, а не две.
- Назначить «Сейчас» из PWA → обновить iOS/виджет → увидеть тот же выбор.
- Завершить задачу в виджете → обновить PWA → она больше не активна.
- Перевести входящую запись в идею → не потерять текст при отказе БД.
- Проверить личные/рабочие фильтры и список более 500 задач без пропусков.
- Получить отказ iCloud → продолжить работу с задачами и увидеть причину
  отсутствия расписания вместо ложного «Встреч нет».
- Проверить истечение сессии, выход, защиту запросов изменения и ограничения
  токена виджета. Секреты не должны присутствовать в кэше браузера.
- Выполнить имеющиеся Python-тесты и новые проверки затронутых операций;
  проверить веб-интерфейс на настольной и мобильной ширине, затем на iPhone.

## Следующее решение

Проверить эту спецификацию, затем подготовить отдельный план реализации.
Код продукта, развёртывание на VPS и сокращение Swift в рамках подготовки
этого документа не выполнялись.
