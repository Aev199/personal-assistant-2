# Веб-интерфейс помощника

Открывается на компьютере и iPhone через браузер по адресу
`https://ВАШ-ДОМЕН/app/`. Использует те же задачи, идеи, встречи и «Сейчас»,
что Telegram и установленное iOS-приложение.

Это первый рабочий веб-этап. Установка PWA, автономная работа, переключение
уведомлений на iOS и сокращение Swift-приложения выполняются отдельно.

## Обновление VPS

Инструкция рассчитана на существующую установку в `/opt/personal-assistant-2`.
Перед обновлением узнайте название службы и текущую версию:

```bash
cd /opt/personal-assistant-2
git status --short
git branch --show-current
git rev-parse HEAD
systemctl list-units --type=service --all | rg -i 'assistant|telegram|bot'
```

Если `rg` отсутствует: `systemctl list-units --type=service --all | grep -Ei 'assistant|telegram|bot'`.
Запишите SHA текущей версии и название службы. Если git показывает изменённые
файлы, сначала сохраните свои правки; команды `reset --hard` здесь не нужны.

Сделайте резервную копию БД используемым на сервере способом. Нужна копия,
которую вы умеете восстановить. Указанный ниже `pg_dump` — пример для сервера,
где клиент Postgres уже установлен и DATABASE_URL задан в текущей оболочке:

```bash
pg_dump --dbname="$DATABASE_URL" --format=custom --file=assistant-before-web.dump
```

Переменные из файла `.env` не появляются автоматически в оболочке. Если
DATABASE_URL там, пользуйтесь существующим механизмом резервного копирования
сервиса. Не запускайте пример с пустой переменной.

Затем загрузите ветку:

```bash
cd /opt/personal-assistant-2
git fetch origin
git switch --track origin/feat/unified-assistant-web
```

Если локальная ветка уже существует, используйте `git switch feat/unified-assistant-web`,
затем `git pull --ff-only`. Если Git сообщает dubious ownership, выполняйте git от
владельца каталога, как в существующей установке; не меняйте владельца проекта
ради обновления.

В файле окружения сервиса добавьте:

```text
ASSISTANT_PUBLIC_ORIGIN=https://ВАШ-ДОМЕН
```

Это только адрес: без `/app/`, без пути, без порта, если используется обычный HTTPS.
Нестандартный HTTPS-порт допустим, но должен точно совпадать с адресом в браузере.
Потребуется уже существующий `ASSISTANT_API_TOKEN`, а если его нет —
`COMPANION_API_TOKEN`. В форме браузера вводится значение этого ключа, а не имя
переменной. `COMPANION_WIDGET_TOKEN` не подходит для входа. Ключ вводите прямо
в форму, присылать его в чат не нужно.

Reverse proxy должен передавать `/app/` и `/api/v1/` в тот же Python-сервис,
сохраняя заголовок Origin. Если proxy уже передаёт все пути, менять его не нужно.
Не добавляйте кэширование `/api/v1/` и страницы `/app/`. Нужен действующий HTTPS:
cookie браузерного входа специально имеет флаг Secure. Доверие произвольным
X-Forwarded-* заголовкам не включается; лимит входа за proxy может быть общим
для всех устройств.

Перезапустите службу, подставив её фактическое имя:

```bash
sudo systemctl restart ИМЯ-СЛУЖБЫ.service
sudo systemctl status ИМЯ-СЛУЖБЫ.service --no-pager
sudo journalctl -u ИМЯ-СЛУЖБЫ.service -n 40 --no-pager
```

Дополнительные зависимости на VPS и отдельный Node-процесс не нужны.
Новые таблицы создаются существующим механизмом запуска приложения.

## Первый вход и проверка

1. Откройте `https://ВАШ-ДОМЕН/health`, проверьте ответ сервиса.
2. Откройте `https://ВАШ-ДОМЕН/app/` и введите ключ приложения.
3. Добавьте короткую тестовую запись; после подтверждения она появится во Входящих.
4. Откройте Telegram/iOS и найдите эту же запись.
5. Назначьте задачу «Сейчас» в браузере и обновите виджет.
6. Завершите тестовую задачу в iOS и обновите страницу.

На телефоне внизу три вкладки: Главная / Задачи / Идеи.
Работа и личное переключаются внутри задач; можно кнопкой или горизонтальным
свайпом по свободной части списка. На компьютере доступны те же разделы сбоку.

Строка сверху — быстрый ввод. Нажмите Enter или кнопку справа. При ошибке текст
остаётся в поле; «Повторить сохранение» использует ту же попытку и не создаёт
вторую запись. Если после сбоя вы набрали другой текст, сначала подтвердите
предыдущую запись кнопкой повтора, затем отправьте новый текст.

Задачи без даты остаются в списке. «Сегодня» показывает короткую подборку;
полный список открывается в «Задачи» с кнопкой «Загрузить ещё».
Входящие — задачи без объекта; их можно изменить или перенести в идеи.
При конфликте редактирования перечитайте карточку и повторите нужные изменения.

Если календарь недоступен, приложение сообщает об этом отдельно. Это не означает,
что встреч нет. Работа с задачами и быстрый ввод продолжаются без Gemini/iCloud.
В открытой вкладке данные обновляются раз в 30 секунд и при возврате к странице;
виджет обновляется по правилам iOS, мгновенное обновление не обещается.

## Откат

Переключите git на записанный до обновления SHA и перезапустите ту же службу:

```bash
git switch --detach ЗАПИСАННЫЙ-SHA
sudo systemctl restart ИМЯ-СЛУЖБЫ.service
```

Новые таблицы `web_sessions` и `capture_requests` можно оставить: предыдущая версия
их не использует. Задачи и идеи сохраняются в прежних таблицах.

## Проверки разработки

```bash
python -m pytest -q
TEST_DATABASE_URL=postgresql://... python -m pytest -q tests/test_web_postgres.py
node --check bot/web/app.js
node tests/web-browser.cjs
```

Для browser-проверки нужен Playwright с Chromium только на машине разработчика.
Postgres-тесты используют случайную отдельную схему и удаляют её после проверки;
TEST_DATABASE_URL должен указывать исключительно на тестовую БД.
В GitHub workflow `web-interface` поднимается изолированный PostgreSQL 16.
Браузерный сценарий использует явно искусственные данные и проверяет пользовательские
действия отдельно от SQL-проверок.
